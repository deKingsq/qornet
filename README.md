# QORNET

Локальная антифрод-платформа для V Өңірлік ITU Hackathon 2026. Сценарии воспроизводят синтетические переводы, сессии, снятие наличных и P2P-сделки в тенге.

- [Сайт проекта](https://dekingsq.github.io/qornet/)
- [Демо для жюри](https://dekingsq.github.io/qornet/demo/)
- [Презентация](https://dekingsq.github.io/qornet/presentation.html)

Онлайн-демо запускает тот же расчёт рисков в браузере и хранит решения в текущей вкладке. Команда `npm run build:pages` собирает его для GitHub Pages. Локальный запуск ниже использует Express и SQLite.

## Запуск на Windows

Нужен Node.js 24 LTS (24.14 или новее) с npm. Двойной щелчок по `Start-QORNET.cmd` открывает сайт проекта. Для репетиции и защиты используйте `Start-Jury-Demo.cmd`. Оставьте окно сервера открытым во время показа.

Из PowerShell в папке проекта:

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run build
npm.cmd start
```

Для разработки с обновлением интерфейса при изменениях используйте `npm.cmd run dev` и откройте адрес, напечатанный Vite. Сервер API слушает только loopback. SQLite хранит дела и журнал в `data/qornet.sqlite`. Для отдельной демонстрации задайте `QORNET_DB` абсолютным путём к новому файлу базы. Порт собранного приложения можно изменить через `QORNET_PORT`.

## Демонстрация

- [Сайт проекта](http://127.0.0.1:4174/) объясняет, как QORNET проверяет получателя, связывает счета и анализирует запрос в банкомате.
- [Демо для жюри](http://127.0.0.1:4174/demo/) содержит шесть шагов. Начните с двух переводов по 252 000 ₸, затем покажите общий Wi-Fi, граф дроп-карт, маршрут денег, проверку снятия и результаты сравнительного теста. Переключайте шаги стрелками влево и вправо. Кнопка в шапке включает полный экран.
- [Кабинет аналитика](http://127.0.0.1:4174/app/) открывает заявки, дела и журнал. Ссылки из демо ведут к результатам проверок.

Оба сайта используют один локальный сервер. Операции симулируются. История трассировки демонстрирует, что могло произойти без раннего вмешательства.

Отдельные сценарии доступны в разделе **«Демо-сценарии»**.

1. **Дропперская сеть.** Откройте граф `CL-4101`, выберите любой узел и покажите, какие сессии и переводы подтверждают связи между счетами.
2. **Обычная активность.** Переключите сценарий. Общий IP виден в графе. Связанные им клиенты получают 0 баллов.
3. **Смена IP и VPN.** Вернитесь к кластеру с изменёнными IP. Сопоставление сохраняется за счёт отпечатков устройств и движения денег.
4. **Цепочка переводов.** Воспроизведите маршрут 252 000 ₸ по шагам. Среди остальных маршрутов найдите цикл и переход между двумя отдельно выявленными кластерами.
5. **Снятие в банкомате.** Отправьте 800 000 ₸ на проверку. Откройте дело, добавьте обоснование и примите решение. Операция и действия сотрудника появятся в журнале. Переключатель RU / ҚАЗ меняет язык терминала.
6. **Социальная инженерия.** Попробуйте снятие по указанию третьего лица. Терминал предлагает прервать разговор и обратиться в банк. «Нужна помощь» отменяет снятие в симуляторе и записывает событие.
7. **P2P-треугольник.** Сверьте участников и условия. Затем назначьте покупателя получателем товара и отметьте подтверждение продавца, чтобы проверить исправленный вариант.

Все сценарии запускают расчёт на сервере. На экране «Движок риска» повторно рассчитываются метрики на 28 синтетических наборах с четырьмя фиксированными seed. Матрица показывает в том числе пропущенные счета. Разметка используется при оценке качества и не передаётся алгоритмам обнаружения.

Там же сравниваются две политики по 48 синтетическим заявкам на перевод: проверка сумм от 200 000 ₸ и проверка получателя по графу. Обе получают одинаковые заявки. Граф строится по событиям до проверяемого перевода. В выборке есть рискованные получатели без истории и обычный перевод участнику связанной сети. Результаты описывают эту выборку.

Для банковского пилота предлагается повторно проиграть обезличенную историю в режиме наблюдения и сопоставить причины QORNET с решениями аналитиков. Метрики пилота — доля обнаруженных случаев, доля ложных тревог и P95 времени от заявки до ответа.

## Устройство системы

- **Frontend** — React, TypeScript, Vite, Cytoscape.js и Recharts. Сеть исследуется через граф и инспектор. Денежный маршрут можно воспроизвести по времени. Шрифты поставляются локально.
- **Backend** — Node.js, TypeScript, Express, Zod и SQLite. Дела, решения и события аудита записываются транзакционно. API и собранный интерфейс доступны на одном локальном адресе.
- **Network** — индексирует синтетические отпечатки устройств. Связь между двумя счетами добавляется при подтверждении финансовыми событиями. Общие получатели-мерчанты исключены из сигнала концентрации. Кластер — связная компонента подтверждённых пар из трёх и более счетов.
- **Trace** — обходит направленный граф во времени. Ищет от трёх до пяти последовательных переводов с интервалом до 15 минут и сопоставимыми суммами. Замыкание выделяется отдельно. Обычные контрагенты не наследуют уровень кластера. Слабый сигнал соседства ограничен 18 баллами и требует двух связанных контрагентов.
- **Core и ATM** — возвращают балл, коды причин, ссылки на события, уровень и рекомендуемое действие. Крупная сумма сама по себе запускает дополнительную проверку. Для приостановки в демо требуется сочетание крупной нетипичной суммы, подтверждённого кластера и быстрой денежной цепочки.
- **Vision** — экспериментальный локальный предпросмотр камеры по явному согласию. Видеопоток не записывается и не используется при оценке риска.

Балл 0–100 складывается из сигналов с ограничением для каждого типа решения. Он не является вероятностью мошенничества. Связанные суммы и время дают гипотезу о маршруте, которую проверяет аналитик. В прототипе используется локальная роль аналитика без банковской системы авторизации. Данные синтетические, а переводы и операции банкомата симулируются.

### API

| Запрос | Результат |
| --- | --- |
| `GET /api/v1/health` | Доступность и режим сервера |
| `GET /api/v1/scenarios/:scenario/snapshot` | Граф, переводы, причины, данные формы |
| `POST /api/v1/scenarios/:scenario/runs` | Новый расчёт, запись в журнал, открытие дел |
| `GET /api/v1/evaluation` | Метрики на размеченных сценариях |
| `GET /api/v1/transfer-benchmark` | Матрицы результатов двух политик на одних и тех же заявках |
| `POST /api/v1/transfer-checks` | Оценка получателя до подтверждения. Повтор с тем же `requestId` возвращает сохранённое решение |
| `GET /api/v1/transfer-checks/:id` | Состояние заявки |
| `POST /api/v1/transfer-checks/:id/resolutions` | Подтверждение разрешённой заявки, отмена или запрос помощи |
| `POST /api/v1/atm-decisions` | Расчёт риска снятия |
| `GET /api/v1/atm-decisions/:id` | Текущее состояние снятия |
| `POST /api/v1/atm-decisions/:id/resolutions` | Подтверждение, отказ или помощь |
| `POST /api/v1/deal-assessments` | Сверка P2P-сделки |
| `GET /api/v1/cases`, `PATCH /api/v1/cases/:id` | Очередь и решение аналитика |
| `GET /api/v1/audit` | Последние события аудита |
